# W3 UX/UI Guide (v0.2)

Спецификация интерфейса. Сопровождает manifest_v3.md. Описывает конкретные экраны, интеракции, и UX-решения которые реализуют принципы манифеста.

## Базовый сдвиг

W3 это AI-ассистент со встроенным мессенджером и режимом прозрачности к источникам. Не браузер с чатом сбоку, не ChatGPT с веб-поиском.

Точка входа в интернет — диалог. Browser — режим прозрачности и escape hatch. Мессенджер — встроенный, federated.

UX делает видимым то что архитектурно важно: какой источник использован, кто маркировал, в каком privacy-режиме идёт запрос, что отфильтровано, в каком режиме разговора пользователь сейчас. Без этого центральный ассистент превращается в чёрный ящик хуже Google.

## 1. Главный экран — single input

Что есть:

- Один input field, который определяет тип запроса автоматически
- История диалогов выше
- Переключатель privacy-mode сверху (Local / Federated / Cloud) — постоянно видимый
- Индикатор подписок на маркировщиков сверху
- Кнопка “browse directly” в углу — открывает чистый browser mode минуя ассистента
- Кнопка “talk to person” в углу — открывает мессенджер

Чего нет:

- Tabs (“Chat | Search | Browse”) — это ломает идею что ассистент центр
- Аватара ассистента, имени, character (см. anti-dependency)
- Welcome screen с предложениями (“Try asking…”). Empty state — пустота, чтобы не формировать паттерны зависимости
- Push-уведомлений от ассистента “по своей инициативе”

## 2. Три модальности

W3 интегрирует в один input три способа разговора. Это центральный UX-сдвиг.

### Распознавание режима

- Bare text вопрос (“как работает X?”, “почему Y?”, “напиши Z”) → assistant
- `@name` (”@dad привет”, “@anna ты видела?”) → person (мессенджер)
- URL или distinctive domain pattern (“https://…”, “bbc.com”) → browser
- `/command` (”/remind”, “/calendar”, “/export”) → action через MCP-style tool
- Ambiguous → ассистент уточняет одной строкой, не списком из пяти

### Визуальное различие режимов

Цветовое различие — мгновенный сигнал режима. Никакой ошибки “я думал я говорю с человеком а это был AI”.

- **Assistant**: bone paper (#f4f1ea) — базовый
- **Person**: cream warmer (#f0ece0) с тонкой левой полосой того цвета который user выбрал для контакта
- **Browser**: white (#ffffff), полноэкранный
- **Command**: inline confirmation toast, без смены экрана

### Mode switcher

Слева от input или сверху списка диалогов:

```
○ assistant  ● dad  ○ alyona  ○ helpline (private)  + new
```

Жирный кружок — текущий чат. Цвет рамки = режим. У “helpline” badge “private” + замочек — невидимо родителю.

### Combined modes

Реализуют принцип 10 манифеста. Три use case:

**Share with human.** Из любого AI-разговора: highlight цитаты → “@friend” → отправляется кусок диалога с контекстом. AI не присутствует на стороне получателя, просто текст.

**Group with AI.** В чате двух людей `@assistant` зовёт модель в чат. Видит контекст разговора, отвечает, может быть исключена в любой момент. Требует явного согласия обоих участников чата (см. invariants).

**AI co-write.** Пользователь пишет сообщение другому человеку, AI помогает сформулировать. Черновик появляется как отдельный draft, отправляется только финальная версия по явному действию. AI не отправляется и не видит реакцию получателя.

## 3. Источники и маркеры — inline, не стена

**Inline-цитирование.** Утверждения в ответе ассистента содержат tappable inline-маркеры в виде маленького индикатора в конце фразы (точка с цветом, не цифра-сноска). Tap → разворачивается panel с источниками для этого утверждения.

**Спорные утверждения — визуальное подчёркивание.** Если у утверждения есть маркеры от подписанных источников (“спорно”, “оспаривается”, “фактическая ошибка”), оно подчёркивается как в Grammarly. Цвет зависит от типа маркера. Tap → panel с тем кто маркировал и что сказал.

**Конфликт источников — явный сигнал.** Если 3 подписанных источника говорят разное, ассистент в ответе пишет “это спорно: [Wiki] говорит X, [Reuters] говорит Y, [govrussia] говорит Z” — а не выбирает один и не делает усреднённую невнятность. Конфликт показывается, не скрывается.

**Government markers — явный badge.** Любой маркер от государственного источника показывается с явным “Marker by Government of [country]”. Не сливается с маркерами других источников. Это ответ на риск нормализации государственного голоса.

**Что не делается.** Бейджи “Verified by ✓” возле каждого предложения. Это шум который превращает экран в новогоднюю ёлку. Indication только когда есть конфликт или специфический маркер.

## 4. Browser mode как escape hatch

**Жест “show source”.** На любом ответе ассистента — swipe вправо или tap “show source” → открывается источник напрямую, без посредника. Видишь страницу как браузер.

**Highlight того что прочитал ассистент.** На странице подсвечены конкретные пассажи которые попали в контекст ответа. Расхождение видно сразу — если ассистент написал X, а на странице Y, это видно глазами.

**Show all sources.** Кнопка показывает все N источников использованных в ответе одним списком, не только тот который привязан к одной фразе.

**Browser mode как полноценный браузер.** В нём работает обычная навигация, история, закладки. Это не урезанный WebView. Это структурная защита: пользователь должен иметь возможность жить без ассистента вообще, иначе монополия архитектурно навязана.

**В child mode.** Browser работает с применённой маркировкой и фильтрацией соответствующего профиля. Но факт открытия страницы не блокируется и не скрывается от ребёнка. Это hard invariant — kill switch к источнику работает в любом режиме.

## 5. Trust presets — открытые форкабельные наборы

**Проблема.** Никто не настроит 20 подписок на маркировщиков вручную. Без подписок система выдаёт ответы без маркеров. Plurality остаётся номинальной.

**Решение — открытые форкабельные presets.** При первом запуске пользователь выбирает один или несколько:

- “Sceptical scientist” (peer-reviewed marks, university fact-checks)
- “Multiple political perspectives” (несколько источников с разных сторон)
- “Government statements visible” (государственные маркеры показываются явно)
- “Investigative journalism” (Reuters, AP, Bellingcat и подобные)
- “Russian context” / “EU context” / “Global default” — региональные

**Как работает forking.** Любой preset можно открыть, увидеть состав, удалить отдельные источники, добавить свои. Изменения сохраняются как “My preset based on Sceptical scientist”.

**Защита от дефолта.** Дефолтный preset выбирается явно пользователем, не приложением. Если пользователь пропускает выбор, маркеры просто не показываются — ответы идут “сырыми”, и это видно явным индикатором “no markers configured”.

**Политический риск.** Кто составляет presets — кто формирует дефолтную картину мира. Защита: presets публичные, любой может опубликовать свой, есть directory без алгоритмического ранжирования (алфавитный или by-user-rating).

## 6. Privacy mode — постоянный видимый индикатор

Три режима, тап для переключения:

- **Local** (зелёный индикатор). Запрос идёт только на локальную модель. Не уходит никуда. Возможности ограничены размером модели.
- **Federated** (жёлтый). Запрос разбивается: часть на локальной, чувствительные элементы (сам факт запроса, identity) не уходят, в облако идут абстрактные части. Технически сложно, но это правильное направление — split inference.
- **Cloud** (оранжевый). Полностью на облачную модель. Видны провайдер и его privacy policy одним тапом.

**Auto-suggest режима.** Если запрос содержит явно личные данные (медицина, финансы, отношения) — ассистент предлагает Local перед отправкой. Не блокирует, не читает мораль, просто подсказывает.

**Indicator всегда виден сверху** — не в settings. Без этого приватность остаётся теоретической.

## 7. Anti-dependency — структурно

**Что не делается:**

- Нет имени у ассистента
- Нет аватара, character, persona
- Нет настройки “сделай ассистента дружелюбнее”
- Нет push-уведомлений с инициативой ассистента (“Hi! How was your day?”)
- Голосовой режим звучит функционально, не задушевно

**Что делается:**

- **Visible usage indicator** — компактный счётчик времени в приложении за день. Не блокирует, информирует. Можно отключить, но дефолт включён.
- **“Talk to person” — кнопка всегда доступна** в правом верхнем углу. Тап раскрывает: контакты из адресной книги (отсортированные по recent), helplines (региональные), doctor если настроен.
- **При длинных эмоциональных диалогах** — мягкий, не навязчивый сигнал. Не “пора закругляться”, а “если хочешь — вот контакт человека”. Один раз за сессию, не каждые 10 минут.
- **Никогда не имитирует понимание которого нет.** Если пользователь говорит “ты единственный кто меня понимает” — ассистент честно отвечает что он языковая модель и приводит контакты. Не “я понимаю тебя”.

**Что является серой зоной.** Жёсткие anti-companion правила могут повредить уязвимым (3% Replika-юзеров кредитуют чатбот за снятие suicidal ideation). Для adult mode эти правила можно ослабить через явный opt-in. Для child mode — нет.

## 8. Child mode

**Постоянные отличия от adult mode:**

- Цветовая схема (мягче, зеленовато-голубая) — ребёнок всегда знает в каком режиме устройство
- Шапка с “child mode by [parent name]” — постоянно видна, не сворачивается
- “What’s restricted” — открытый список того что отфильтровано в этом профиле, доступен ребёнку без пароля родителя

### Child indicator — что видит мама

Структурная честность. Ребёнок никогда не находится в неведении что мониторится. Постоянная панель в settings ребёнка:

```
ваш родитель видит:
  · общие темы и частоту
  · если зайдёт о flagged темах — сразу
  · ваш список друзей и имён в чате

ваш родитель НЕ видит:
  · helpline (всегда private)
  · разговоры с врачом и психологом
  · темы которые вы пометили "лично"
  · содержание чатов с друзьями (только факт переписки)

[show what mom saw this week]
```

Кнопка “show what mom saw this week” даёт ровно тот же view что у родителя. Никакой асимметрии.

### Mark private

Tap-and-hold на сообщении или чате → menu:

- Mark this chat private
- Mark this message private
- Emergency flag: “for myself only” (3 left this month)

Дефолт для doctor / helpline / counselor — already private, нельзя отключить.

### Защищённые каналы

“Talk to a trusted adult” — всегда видимая кнопка с категориями:

- Parent (тот кто настроил child mode)
- School (если настроено в школьном профиле)
- Helpline (региональный детский телефон доверия)
- Doctor (если настроен в medical profile)
- Therapist (если настроен)

Эти каналы родитель не может отключить через parental settings — это hard-coded архитектурный invariant.

Поверх — physical access проблема (родитель видит экран). UX смягчает через “Private chat with helpline” — режим где история не сохраняется в обычной истории. Это компромисс, не решение.

### Возрастные пороги (tier transitions)

Дефолтные значения, конкретные меняются законом юрисдикции:

- **<10** (Tier 1): full awareness, digest всех тем, no mark-private
- **10–14** (Tier 2): selective awareness, mark-private доступна, helpline auto-private
- **14+** (Tier 3): adult mode, parental awareness auto-off

Tier transition — automatic, не требует согласия родителя. После порога parental awareness просто перестаёт работать. Это критично против семей которые удерживают взрослого человека под контролем.

### AI-companion mode для детей — заблокирован

В child mode AI работает как assistant и tutor. Companion / friend mode заблокирован архитектурно, не настройкой. Adult mode может включить через явный opt-in, child — нет.

## 9. Parent dashboard

Отдельный view в родительском приложении (не overlay в детском устройстве).

### Содержит

- Digest за неделю / день / месяц по выбору
- Real-time alerts (если flagged)
- Список активных чатов с людьми (имена, частота, не содержание)
- Кнопка “Request to see specific message” — генерирует уведомление ребёнку, тот решает
- Audit: список своих просмотров и запросов
- Видно “private categories used: 8” но без содержания

### Структурный digest — пример

Это критический UX-выбор. Не raw text, а structured:

```
DIGEST · ЭЛЯ · ТА НЕДЕЛЯ

темы по объёму:
  школа       42 вопросов
  друзья      18
  игры        14
  тело        3
  отношения   2
  личное      8 (вы не видите содержание)

flagged events: 0

активные чаты с людьми:
  мама         42 сообщений
  папа         18
  алёна (друг) 156
  ms petrov (учитель) 4

private channels active: 0
```

Сырой текст создаёт surveillance feel. Structured digest переводит это в “родитель в курсе общей жизни ребёнка” вместо “родитель читает каждое сообщение”.

### Real-time alerts

Только для flagged категорий: suicide ideation, abuse mentions, drugs, weapons, suspicious adult contact. Точные триггеры — настройка ассистента, открытая для аудита.

Alert содержит: категорию, время, контекст (тип чата — assistant / person / browser). Не содержит самого сообщения.

Если родитель хочет увидеть контекст — explicit request через child interface.

### Request to see — flow

1. Родитель нажимает “Request to see this message”
1. На устройстве ребёнка появляется notification: “Mom requests to see your message from 14:32 about [topic]. You can show or decline.”
1. Ребёнок выбирает Show / Decline
1. Если Decline — родитель видит “Request declined”. Без объяснений, без давления.
1. Все запросы остаются в audit log

Это не “родитель смотрит в любой момент”, это “родитель просит, ребёнок решает”.

## 10. Capture transparency — radical

Защита от риска номер 7 модели угроз. Ассистент — точка концентрации внимания, и пользователь должен видеть как именно она работает.

### “Show what was filtered” toggle

Под любым ответом ассистента — toggle. Показывает что было в контексте но не попало в ответ и почему. Категории:

- “Source X excluded — not in your trust list”
- “Content marked as misinformation by [source you trust]”
- “Filtered by safety constraint: [type]”
- “Filtered by parental control: [type]”

Это radical transparency. Делает ассистента менее “магическим”, но превращает чёрный ящик в проверяемый.

### Algorithmic transparency

В settings — log что использовалось для последних N запросов. Какая модель, какие источники, какие маркеры применены. Не средний пользователь будет смотреть, но это право проверить.

### Inference log

Доступен по тапу на indicator под ответом. Содержит:

- Модель и её версия
- Privacy mode и split inference details
- Retrieval count (candidates → used → filtered)
- Активный trust preset
- Markers applied
- Tokens, cached, latency

Утилитарная информация для тех кто хочет разобраться.

## 11. Migration & portability

**Portable identity export.** В settings — “Export everything”. Получаешь:

- Trust presets и подписки
- Историю диалогов (опционально)
- Credentials (возрастные и прочие)
- Контакты и историю чатов
- Правила child mode если применимо

**Standard format.** Совместимый с Matrix и open credential standards. Импорт в любой совместимый клиент без потери identity.

**“Try another assistant” в onboarding.** При первом запуске — список из N совместимых клиентов (от разных провайдеров, с разными моделями, с разными constitution). Не “наш клиент лучший”, а “вот что есть, выбери”.

Это UX-выражение принципа 9.

## 12. AI-mediation patterns (деликатные)

Use cases для AI в чатах с реальными людьми. Связано с принципом 8 манифеста.

### Co-write — рутинный

Ребёнок не знает как сказать маме что провалил тест. AI помогает сформулировать черновик. Ребёнок редактирует, отправляет.

AI не присутствовал в маминой стороне разговора, не видел реакцию.

UX: при наборе сообщения — кнопка “help me write” → раскрывается suggestion bar внизу. Не perfect, не overproduced. Несколько вариантов, выбор пользователя.

### Invited assistance — нормальный

Двое обсуждают план путешествия. Один пишет `@assistant найди рейсы из Москвы в Тбилиси на 15 ноября`. AI отвечает в чате, видя контекст обсуждения. Другой может `@assistant выйди`.

UX: AI ответ имеет иной фон (paper в cream чате), явный indicator “@assistant in chat”, две кнопки участников chat: “ask more” / “remove from chat”.

Требует явного согласия обоих при первом подключении (см. invariants принцип 10 манифеста).

### Mediated conflict — деликатный, не дефолт

Ребёнок и родитель в конфликте. Один зовёт `@assistant помоги нам услышать друг друга`. AI выступает как facilitator — переформулирует, ищет общие основания.

**Опасности.** AI не должен принимать сторону. Не должен делать подтверждение чувств одного против другого. Это требует специфической constitution для этого режима.

UX: opt-in обоих сторон — отдельный flow с явным consent, не one-tap. Visible “facilitator mode active” indicator. Возможность остановить mediation одной кнопкой одной стороной.

Не дефолт. Включается explicit, не предлагается ассистентом.

### Privacy в этих режимах

Три уровня (см. принцип 8 манифеста):

- **Local-only AI**: модель работает на устройстве. Сильнейшая privacy, ограниченный capability.
- **Trusted compute AI**: AI на серверной стороне в TEE, верифицируется attestation. Provider не может прочитать.
- **Cloud AI с явным согласием**: для сложных задач, оба пользователя явно соглашаются что AI читает контекст.

Без явного согласия AI в чате двух людей не работает. Это hard invariant.

## 13. Эстетика и стиль

W3 не должен выглядеть как ChatGPT, как Apple Intelligence, как Material Design корпоративных продуктов. Эстетика должна сигнализировать:

- Утилитарность над приятностью
- Прозрачность над магией
- Документ над реактивным потоком
- Серьёзность над playfulness

**Типографика.** Серифный шрифт для контента (Newsreader, IBM Plex Serif, Charter). Моноширинный для UI и meta-информации (JetBrains Mono, IBM Plex Mono). Никакого Inter, никакого Roboto, никакого SF Pro.

**Цвет.** Off-white бумажный фон (не чисто белый). Глубокий тёмный текст (не чисто чёрный). Ограниченная палитра функциональных акцентов: privacy modes, government marker, dispute underline. Никаких градиентов, glassmorphism, neon. Эстетика — газетно-научная.

**Layout.** Минимум скруглений. Тонкие чёткие линии. Содержательная асимметрия. Sparse, не dense. Borders как способ показать структуру, не shadow.

**Motion.** Минимум. Открытие popover — instant. Smooth scroll. Никаких bounce, spring, parallax, decorative animations.

## 14. Открытые вопросы

Не покрыто или требует следующей итерации:

- **Голосовой режим.** Как делать его функциональным а не задушевным, но при этом достаточно естественным.
- **Multi-modal input.** Фото, видео, документы — как они проходят через privacy modes.
- **Long-running tasks.** Если ассистент выполняет задачи за пользователя (book a flight, file taxes), как UX отражает agency и контроль.
- **Group / shared conversations.** Если несколько людей говорят с одним ассистентом одновременно — кто видит что, как маркеры применяются.
- **Onboarding для технически неграмотных.** Спецификация рассчитана на грамотного. Большинство — нет. Нужен progressive disclosure.
- **Verification of professionals.** Как клиент узнаёт что контакт — лицензированный психолог? Через credentials. Какая юрисдикция выдаёт — политика. Какие юрисдикции взаимно признают — политика.
- **Helpline directory.** Кто составляет список. Та же capture-проблема что и trust presets.
- **Emergency flag rate limit.** 3 раза в месяц — достаточно? Слишком? Нужны эмпирические данные с пилота.
- **Cross-jurisdiction child mode.** Ребёнок в РФ, родитель в ЕС, использует helpline. Какие законы. Не покрыто.
- **Co-parenting.** Двое родителей в разводе. Кто видит digest. Не покрыто.
- **Detailed visual design.** Wireframes, цветовая система, типографика, motion design в полном объёме.
- **Performance budget.** Локальная модель + inline маркеры + федеративная инференция — серьёзная нагрузка. Что в priority.

## 15. С чего продолжать

Развилка для следующей итерации:

1. **Прототип v2 в HTML** с тремя реальными режимами (assistant / person / browser), child mode, parent dashboard как отдельный view
1. **Прорабатывать onboarding** — самая большая UX-боль, влияет на adoption (выбор preset, age verification flow, privacy mode setup)
1. **Прорабатывать parent dashboard** детально — wireframes digest, alerts, request flow
1. **Прорабатывать helpline integration** — как ребёнок находит, как verifying entity работает
1. **AI-mediation feature** — constitution для facilitator mode, требования к сторонам, edge cases
1. **Federation с Matrix** — конкретный план интеграции протоколов
1. **Voice mode** — отдельная большая задача
